# LATTICE demo: a real three-agent OSINT investigation

Everything in this folder was generated by running the OSINT example
shipped in `examples/osint_investigation.py` against a file-backed
LATTICE store, then capturing the CLI views and the dashboard so the
output is reproducible and inspectable.

## What it shows

A small three-agent investigation: `harvester` (collector),
`analyzer` (cross-references), `reporter` (final assessment).

The investigation deliberately includes one over-confident claim
(an APT-99 attribution drawn from circumstantial evidence) so the
audit pass has a real defect to flag and the revocation waterfall
has a real cascade to demonstrate.

## How to regenerate

When LATTICE features change and the screenshots need a refresh:

```bash
# 1. Build the demo investigation and capture Rich SVGs
python3 docs/demo/source/lattice_demo.py
# Writes:
#   /tmp/lattice_demo_workspace/.lattice/lattice.db   (the investigation)
#   /tmp/lattice_screenshots/*.svg                    (CLI snapshots)

# 2. Start the dashboard pointed at that workspace
python3 docs/demo/source/lattice_dashboard_server.py &
DASH_PID=$!

# 3. Convert SVGs to PNGs and capture the dashboard
#    Requires bun and a Playwright install. Any project with
#    playwright in node_modules works; the script imports from
#    forenix-oss as an example. Change the cwd if you have your
#    own.
bun docs/demo/source/lattice_screenshots.ts

# 4. Tidy up
kill $DASH_PID

# 5. Copy the fresh PNGs in
cp /tmp/lattice_screenshots/png/*.png docs/demo/screenshots/
```

## Source (`source/`)

| File | Purpose |
|------|---------|
| `lattice_demo.py` | Builds the demo investigation against a file-backed store and exports five Rich SVG snapshots |
| `lattice_dashboard_server.py` | Stands up the FastAPI + D3 dashboard against the demo workspace at port 8765 |
| `lattice_screenshots.ts` | Bun + Playwright script that converts the SVGs to PNGs and captures the dashboard |
| `*.svg` | The Rich console SVG outputs (source for the screenshot PNGs) |
